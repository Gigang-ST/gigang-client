# ADR-0007: 마일리지런·PB 클래스 프로젝트는 기강 전용으로 두고 다른 팀용으로 일반화하지 않는다

- 상태: 승인
- 날짜: 2026-11-09
- 결정자: Junmin Kim (PR #649 작업 중 결정)
- 대체: 없음

## 맥락

멀티팀(울산지부) 분리 중, 마일리지런 금액이 코드 상수로 박혀 있는 게 나왔다(`lib/mileage.ts` — 보증금 월 10,000원,
참가비 20,000원 / 싱글렛 보유 10,000원). 신청·환급 현황·크루 통계·MCP 다섯 곳이 이 상수를 같이 읽고, 환급 현황과
크루 통계는 저장된 금액이 아니라 상수로 다시 계산한다. 싱글렛은 기강 굿즈다.

PB 클래스(동계훈련)는 프로젝트마다 금액 설정(`evt_pb_cfg`)이 있지만, 회차 구성·훈련팀·점수 규칙이 기강 운영 방식 그대로다.
울산은 프로젝트를 막지 않고 빈칸으로 두기로 했다(#650) — 그러면 울산 관리자가 마일리지런을 만들면 기강 금액이 그대로 적용된다.

## 결정

1. `MILEAGE_RUN`·`PB_CLASS` 두 프로젝트 타입은 **기강 전용**으로 본다. 다른 팀에서 쓰도록 금액·규칙을 일반화하지 않는다.
2. 다른 팀이 비슷한 프로젝트를 하게 되면, 그 팀 방식에 맞춰 **새 프로젝트 타입**을 만든다(방식이 다를 것이라 기존 타입을 고쳐 쓰지 않는다).
3. 그래서 마일리지런 금액 상수는 그대로 둔다.

## 고려한 대안

- 마일리지 프로젝트마다 금액 설정을 두고(PB의 `evt_pb_cfg`처럼) 다섯 곳이 그 값을 읽게 일반화 — 다른 팀이 같은 방식으로
  할지조차 정해지지 않아 무엇을 설정으로 열어야 할지 모른다. 돈 계산(기강 환급)까지 건드리는데 얻는 게 불확실하다.

## 결과

- 기강 마일리지런·PB 클래스 코드는 지금 그대로 둔다. 상수 옆에 이 ADR을 적어 둔다(`lib/mileage.ts`).
- ~~후속: 다른 팀 관리자 화면에서 이 두 타입을 새로 만들 수 있는 길이 남아 있으면 막는다~~ → **막지 않는다**(2026-11-10 유저 결정).
  다른 팀도 만들 수는 있고, 만들면 기강 금액·규칙이 그대로 적용된다. 그 팀이 실제로 쓰게 되면 그때 위 2번(새 타입) 또는

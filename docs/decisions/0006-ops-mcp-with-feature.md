# ADR-0006: 기능을 추가·변경하면 운영 MCP 도구도 같은 PR에서 넣는다 — 안 넣으면 이유를 PR에 적는다

- 상태: 승인
- 날짜: 2026-11-08
- 결정자: @LHG4650 (이슈 #641)
- 대체: 없음

## 맥락

운영진은 자기 AI 비서에 붙인 운영 MCP(`app/api/mcp`, `gigang-ops`)로 모임 개설·일정 소식 등록·단톡방 공지 같은
일을 처리한다. 그런데 기능이 사이트에만 생기고 MCP에 빠지면, 운영진은 그 일만 다시 웹에서 손으로 해야 하고
나중에 MCP 도구를 따로 이슈로 만들어야 한다(누락). 기능을 만들 때 같이 넣는 편이 맥락이 살아 있어 싸다.
첫 적용 대상은 #349(하이록스 랭킹보드)다.

## 결정

1. **기능을 추가·변경하면 운영 MCP 도구도 같은 PR에서 추가·변경한다.**
2. **MCP에 안 넣을 거면 이유를 PR 본문에 적는다.** PR 템플릿(`.github/pull_request_template.md`)의
   「운영 MCP 반영」 항목에 `반영함` / `해당 없음: 이유` 중 하나를 고른다. 빈칸으로 두지 않는다.
3. 도구를 넣는 방법은 `app/api/mcp/README.md` §7(도구 추가·변경 절차)을 따른다.

## 고려한 대안

- 필요할 때 MCP 도구를 따로 이슈로 만든다(지금까지의 방식) — 누락이 생기고, 나중에 만들 때 기능의 맥락을 다시
  파악해야 해서 택하지 않았다.

## 결과

- 쉬워지는 것: 운영진이 새 기능을 MCP로 바로 쓸 수 있다. 리뷰어가 PR 템플릿 항목으로 반영 여부를 확인할 수 있다.
- 어려워지는 것: 기능 PR이 커진다. 서버 액션은 세션 쿠키에 묶여 MCP에서 그대로 못 부르므로, 도메인 로직을
  `lib/` 코어로 빼는 작업이 같이 따라온다(`AGENTS.md` 참고 문서 절의 경고).
- 이 규칙을 강제하는 자동 검사는 없다 — PR 템플릿 항목과 리뷰로 지킨다.

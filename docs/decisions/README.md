# 결정 기록 (ADR)

**"A와 B 중 A로 정했다, 이유는…"** 을 남기는 곳이다. 결정과 다르게 하려면 **새 ADR부터** 쓴다
(코드나 DESIGN.md만 바꾸면 다음 사람이 옛 결정을 근거로 되돌린다).

| 번호 | 제목 | 상태 |
|---|---|---|
| [0001](0001-adr-adoption.md) | 결정은 `docs/decisions/`에 ADR로 남기고, 기능 PR 안에서 같이 쓴다 | 승인 |
| [0002](0002-remove-maintenance-mode.md) | 점검 모드를 없애고 화면만 보관한다 — 요청마다 과금되는 호출을 proxy에 두지 않는다 | 승인 |
| [0003](0003-point-visibility.md) | 기강 포인트는 본인 프로필탭에서만 숫자로 보이고, 적립 규칙은 어디에도 적지 않는다 | 승인 |
| [0004](0004-red-dot-rule.md) | 햄버거 아이콘엔 빨간 점을 달지 않는다 — 안읽음 점은 더보기 안 각 줄에만 | 승인 |
| [0005](0005-gathering-exemption-project.md) | 모임 참석 조건의 OR 면제는 모임별 설정(`exm_evt_id`)으로 둔다 | 승인 |

## 무엇을 어디에 쓰나

| 쓰려는 것 | 자리 |
|---|---|
| "앞으로 이렇게 일한다" (규약·컨벤션) | `AGENTS.md`, `.claude/docs/coding-standards.md` |
| "A와 B 중 A로 정했다, 이유는…" | **여기** (`docs/decisions/`) |
| 화면 규격 — 토큰·컴포넌트·간격 | `DESIGN.md` |
| "이거 하면 터진다" (함정·실측 사실) | `.claude/docs/KNOWLEDGE.md` |
| 기능 하나의 설계 전체 | `docs/superpowers/specs/`, `docs/design/` — ADR은 여기를 링크한다 |

**ADR이 필요한 결정**: 되돌리기 비싼 것(데이터 모델·마이그레이션), 외부 서비스·과금 구조, 운영 정책(무엇을 누구에게 보이나),
**같은 얘기가 두 번 나온 것**. 사소한 구현·UI 선택에는 쓰지 않는다 — 그건 코드 주석이나 DESIGN.md 몫이다.

## 쓰는 법

1. [`0000-template.md`](0000-template.md)를 복사해 다음 번호로 만든다. 파일명 `NNNN-짧은-영문-제목.md`.
2. **결정을 낳은 그 PR 안에서** 같이 쓴다. 상태는 처음부터 `승인` — 머지가 곧 기록이다
   (따로 결정 이슈·승인 단계를 두지 않는다. 이유는 [ADR-0001](0001-adr-adoption.md)).
3. 위 표에 한 줄 더한다. 관련 문서(DESIGN.md·AGENTS.md·설계 문서)의 해당 자리에 `(ADR-NNNN)` 포인터를 단다.
4. **승인된 ADR 본문은 고치지 않는다**(오타·링크 제외). 결정을 바꾸려면 새 ADR에 `대체: ADR-NNNN`을 쓰고,
   옛 ADR은 상태만 `대체됨 (ADR-MMMM)`으로 바꾼다. 옛 결정이 왜 그랬는지가 사라지면 같은 실수를 다시 한다.
5. 숫자·실측은 출처와 함께(prd 실측일, PR 번호). 백필할 때 원 기록에 없는 이유·대안을 **지어내지 않는다**.

## 1. 문제

**오픈채팅 비밀번호를 다시 찾을 길이 사실상 없다.** 문의가 반복해서 들어온다.

비번이 나오는 곳은 둘뿐이었다.

| 자리 | 문제 |
|---|---|
| 온보딩 완료 화면 (`member-onboarding-form.tsx`) | 비번 + 참여 버튼까지 잘 차려져 있는데 **1회성**이다. 지나치면 다시 못 온다 |
| 전광판 지면 맨 아래 Social 4칸 (`story-client.tsx`) | 리드 → 심박 → 깅스타그램 → 새얼굴 → 활동량 → 현상수배 **다음**. 판권면이라 의도적으로 안 보이는 자리다 |

그리고 **햄버거 뒤(`/settings`)엔 소셜이 한 줄도 없었다.** 사람이 뭘 못 찾을 때 여는 방이
거기인데 답이 없으니 문의로 흘렀다.

실제로 들어오는 문의는 세 종류였다(운영진 확인):

1. "채팅방 어떻게 들어가요?" — 앱에서 볼 수 있다는 걸 아예 모름
2. "비번 어디서 봐요?" — 있는 건 아는데 못 찾음
3. 재진입 — 나갔다 다시 / 폰 교체

### 곁가지로 드러난 것 — 설정 화면이 잡다하다

7섹션 18줄. 성격 구분 없이 한 줄로 늘어서서 프로필 수정과 이용약관과 다크모드가 같은 무게로
읽혔다. 한 줄짜리 섹션이 둘(`TEAM`·`ADMIN`), `INFORMATION` 5줄 중 3줄이 약관.

**근본 원인은 줄 수가 아니라 성격 혼재다.** 이 화면은 설정 + 네비게이션 + 게시판 + 법적 문서를
한 통에 담고 있었다. 특히 **`/races`로 가는 실사용 진입점이 이 화면의 "대회 목록" 한 줄뿐**이라
(`components/home/upcoming-races.tsx`의 "모두 보기"는 스토리북에만 남은 죽은 코드였다),
설정이 네비게이션 대체재로 쓰이고 있었다.

## 2. 하지 않기로 한 것 — 먼저 말 걸기

가입만 하고 채팅방에 안 들어온 사람에게 배너나 알림으로 찔러주는 안을 검토했고, **버렸다.**

**앱은 누가 채팅방에 들어왔는지 알 방법이 없다.** 카카오 오픈채팅 참여 여부를 조회할 경로가
없으므로 전원 발송이 된다. 그런데 대부분은 이미 들어와 있어서, **소수를 위해 다수에게 노이즈를
보내는 꼴**이다. 배너를 추가하는 안은 더 나쁘다 — 이미 앱 설치(`PwaInstallPrompt`)·푸시 권한
(`PushPermissionPrompt`) 배너가 둘 떠 있어서, 갓 가입한 사람 화면 위에 상자가 셋 쌓인다.

> 나중에 참여 여부를 알 수 있게 되면(예: 자기 신고 체크) 그때 다시 검토한다. **지금은 자리만
> 고친다.**

## 3. 결정

### 3.1 골격 — 한 화면, 두 덩어리

햄버거 아이콘은 `Menu`(더보기)인데 목적지 제목은 "설정"이었고 내용물은 더보기였다. 이름과 내용을
맞춘다.

- **주소는 `/settings` 그대로.** 북마크·알림 딥링크·`InfoBackHeader`의 `/mcp-tokens` 강제
  href가 전부 이 경로를 가리킨다. 바꾸면 다 깨지는데 얻는 게 없다.
- **헤더에 제목은 안 단다.** 처음엔 제호 "더보기"를 세웠다가 걷어냈다 — 방금 누른 햄버거 바로
  다음 화면이고 맨 위 소셜 격자가 이미 이 방의 얼굴이라, 제목 줄이 설명 없는 머리띠로만 남았다.
  **코드·문서에서 이 화면을 "더보기"라 부르는 것과는 별개다.**
- **위 = 어디론가 가는 문 / 아래 = 한 번 정하거나 평생 안 누르는 것.** 사이를 굵은 띠
  (`h-2 bg-secondary`, `px-6` 바깥이라 전폭) 하나로 가른다.

depth를 늘려 설정을 하위 화면으로 접는 안도 있었으나, **띠 하나로 층을 만드는 쪽**을 택했다.
다크모드까지 한 탭이고, 이 앱의 진짜 설정은 5줄뿐이라 화면 하나를 뗄 만큼 무겁지 않다.

### 3.2 배치

| 덩어리 | 그룹 | 줄 |
|---|---|---|
| **더보기** | `SOCIAL` | 채널 4버튼(`SocialTiles`) |
| | `MY` | 프로필 수정 · 계좌 정보 · 회비 내역 · 건의하기 |
| | `CREW` | (관리자 페이지) · 공지사항 · 업데이트 · 대회 목록 · 기강 소개 |
| **설정** | `앱 설정` | 다크모드 · 주 시작 요일 · MCP 토큰 |
| | `계정` | 로그아웃 · 회원 탈퇴 |
| | 푸터 | 이용약관 · 개인정보 처리방침 · 운영 정책 / 버전 |

**7섹션 18줄 → 5섹션 14줄.** 다만 진짜 변화는 줄 수가 아니라 **다음 항목의 자리가 정해졌다**는
것이다 — "눌러서 어디론가 가나?"가 그 질문이다.

옮긴 것들의 이유:

- **`TEAM`·`ADMIN` 섹션 해체 → `CREW`로 흡수.** 섹션 이름만 있고 내용이 한 줄이면 그 이름은
  정보가 아니라 여백이다. 관리자 줄은 primary 색이 이미 "관리자 것"을 말한다.
- **관리자 페이지는 `CREW` 맨 위.** MY로 보내는 안도 검토했다(관리자는 *내* 역할이니까). 하지만
  MY 넷은 전부 `/profile/*` 아래 **폼 하나 고치고 나오는 잎사귀**인 반면 `/admin`은 하위 20여
  개를 거느린 **다른 구역으로 가는 문**이라, 대회 목록·기강 소개와 한 무리다. 그 안에서 맨 위인
  건 운영진이 이 화면에서 가장 자주 누르는 줄이기 때문이다.
- **"도움말 및 지원" → "기강 소개".** 목적지(`/join`)는 크루 소개·모임장소·회칙인데 이름이
  딴소리를 했다. 문의 창구는 "건의하기"가 이미 맡고 있다.
- **MCP 토큰 → 아래 덩어리.** 예전엔 프로필 수정 바로 옆이라 일반 회원 눈에 제일 먼저 걸렸는데,
  이름만으론 뭔지 알 수 없는 개발자용 기능이다. `AI 도구 연결용` 캡션을 붙였다.
- **약관 3줄·버전 → 푸터.** 눌릴 일이 거의 없는 법적 문서가 한 섹션의 대부분이었다. 법적으로는
  접근 가능하면 충분하고 푸터가 원래 그 자리다. `py-2`로 세로 히트 영역은 벌린다.
- **대회 목록은 남긴다.** `/races`로 가는 유일한 길이라 지우면 대회 목록에 갈 수 없다(§5).

### 3.3 소셜

- **화면 최상단.** 못 찾는 사람이 여는 방의 첫 칸이 답이어야 한다.
- **격자는 홈과 같은 컴포넌트.** `SocialLinksGrid`에서 격자+다이얼로그를 `SocialTiles`로 떼어내
  둘이 공유한다. 따로 만들면 채널이 하나 늘 때 한쪽만 고쳐 어긋난다. **헤더만 지면이 각자
  그린다** — 홈은 전광판 존 괘선(`StoryZoneHeader`), 더보기는 목록의 다른 그룹과 같은
  `SectionLabel`. 헤더까지 공유하면 지면 하나가 남의 어휘를 뒤집어쓴다.
- **홈 판권면은 안 걷어낸다.** 중복이지만 **발견 채널을 둘로 두는 게 이 건의 목적**이고,
  판권면은 그 지면의 마감 장치이기도 하다.
- 설명 문구(`SOCIAL_HELP_TEXT`)는 상수 하나를 둘이 공유한다. 각자 타이핑해 두면 한쪽만 고쳐져
  "여기선 비번이 보인다던데" 같은 어긋남이 생긴다.

### 3.4 딥링크 — `/settings?social=kakao`

**문의 대응 비용을 0으로 만드는 게 이 파라미터의 목적이다.** 지금은 문의마다 "홈 맨 아래로
내려가서 카톡 아이콘 누르시면…"을 타이핑해야 하는데, 링크 한 줄이면 끝난다.

- 구현은 `/profile?ttl=history`(칭호 이력 시트)와 **같은 방식** — 클라이언트에서
  `useSearchParams()`로 읽어 `useEffect`로 연다.
- **비번 조회는 다이얼로그가 열리는 순간에 건다.** 예전엔 클릭 핸들러 안에 있었는데, 그대로
  두면 딥링크로 열린 다이얼로그가 조회를 영영 안 해 스피너에 머문다. 여는 길이 둘이어도 조회
  경로는 하나여야 한다.
- **링크가 새어 나가도 비번은 안 나간다** — `getKakaoChatPassword()`가 서버에서
  `getCurrentMember()`로 멤버 여부를 다시 판정한다. 비회원에겐 로그인 안내가 뜬다.

### 3.5 `(info)` 화면 제목

이 레이아웃은 오래도록 **뒤로가기 화살표만 있는 빈 머리띠**였다. `BackHeader`는 `title` prop을
이미 받고 있었는데 `InfoBackHeader`가 안 넘기고 있었다.

**맵에 없는 경로는 제목 없이 둔다** — 그게 안전한 폴백이다. 실제로 넣은 건 **눌러서 도착하는
잎사귀 폼 화면 넷**이다.

| 경로 | 제목 |
|---|---|
| `/profile/edit` | 프로필 수정 |
| `/profile/bank` | 계좌 정보 |
| `/profile/dues` | 회비 내역 |
| `/profile/feedback` | 건의하기 |

제외한 이유가 둘이다. **본문에 자기 제목이 이미 있는 화면** — `/join`·`/terms`·`/privacy`·
`/policy`는 큰 `<h1>`을, `/admin`은 `<H2>`를, `/mcp-tokens`는 `Body font-semibold` 제목을 이미
본문 맨 위에 세우고 있어서, 여기에 또 달면 같은 말이 60px 안에서 두 번 나온다. 그리고 **어디인지
물을 일이 없는 화면** — `/settings`가 그렇다(§3.1).

매칭은 **완전 일치**다. `startsWith`면 관리자 하위 20여 개가 전부 부모 이름을 뒤집어쓴다.

## 5. 범위 밖 — 남은 것

**`/races`로 가는 길이 더보기 한 줄뿐이다.** 설정이 네비게이션 대체재로 쓰이는 이 구조가
"잡다해짐"의 진짜 원인인데, 이번 건에서는 못 고친다 — 일정탭이나 랭킹탭에서 대회로 가는 길을
따로 내야 여기서 뺄 수 있고, 그건 탭 구조를 건드리는 별도 결정이다.

`components/home/upcoming-races.tsx`는 스토리북에서만 쓰이는 죽은 코드다. 위 건을 다룰 때 같이
정리하거나 지운다.

## 6. 아직 눈으로 못 본 것

터미널 검증만 했다. 브라우저에서 확인이 필요한 것:

1. **딥링크 `/settings?social=kakao`가 실제로 다이얼로그를 여는가.** 다이얼로그를 여는 게
   `useEffect`라 `renderToStaticMarkup`으로는 못 잡는다(환경도 jsdom이 아니라 node). PPR
   (`cacheComponents: true`) 아래서 `useSearchParams()`가 하이드레이션 뒤 채워지며 effect가
   도는 경로인데, 같은 패턴이 이미 `/profile?ttl=history`로 돌고 있어 문제는 없을 것으로 본다.
2. **띠(`h-2`)가 전폭으로 나오는가.** `px-6` 바깥에 뒀으니 앱 셸 폭까지 가야 한다.
3. **소셜 4버튼이 375px에서 안 깨지는가.** 홈과 같은 컴포넌트지만 더보기는 좌우 패딩이 같고
   위 여백만 다르다.
4. 라이트/다크 양쪽.

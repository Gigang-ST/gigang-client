# 모임별 OG 카드

`/schedule?gthr=<short_id|uuid>` 딥링크를 카톡에 붙이면 예전엔 **모든 모임이 같은 미리보기**를 냈다
(루트 `metadata` + `app/opengraph-image.png`). 2026-09-21에 조사·시안, **2026-09-22에 구현**(C안 — 종목색 날짜 블록).

시안: **`2026-09-21-모임-og-카드-시안.html`** (같은 폴더, 브라우저로 열면 됨 — 1200×630 실측 4안 +
카톡 말풍선 실제 크기 시뮬레이션)

## 구현 (2026-09-22)

구현하며 정한 것:

- **날짜 블록은 종목색이 아니라 board(검정)다**(2026-09-23, 실제 정기런으로 뽑아 본 뒤 변경). 시안 C안은
  블록을 종목색으로 칠했는데, 실제 모임이 거의 전부 러닝이라 카톡방이 주황 카드로만 채워지고 크루
  정체성(검정 전광판)이 안 보였다. 종목은 오른쪽 칩 하나가 말한다 — 칩 색은 여전히 `--sport-*`.
- **맨 위에 슬로건 `NO TIME TO BE WEAK`** — 홈 헤더 티커와 같은 어법(black·italic·uppercase).
  이탤릭 폰트를 따로 싣지 않고 `skewX(-10deg)`로 기울인다(폰트 하나 더 실으면 +400KB).
- **D-day는 이미지·설명 어디에도 안 싣는다.** 카카오가 URL별 스크랩 결과를 오래 캐시해 스크랩 시점의
  `D-3`이 당일에도 그대로 보인다. 날짜·요일은 틀리지 않는다.
- **캐시 태그는 새로 안 판다.** `getCachedGatheringOg`가 `HOME_CALENDAR_CACHE_TAG`를 같이 쓴다 —
  모임 생성·수정·삭제 액션이 이미 그 태그를 `updateTag`하므로 OG도 같은 순간에 털린다. 태그를 따로 파면
  세 액션에 호출을 하나씩 더 심어야 하고 하나만 빠뜨리면 옛 제목이 한 시간 남는다.
- **이미지 URL에 `v=upd_at`.** 내용이 바뀌면 URL이 바뀌므로 라우트 응답은 `immutable`로 길게 캐시한다.
- **이미지 URL은 요청 호스트로 절대경로를 만든다**(`getRequestOrigin()`, 2026-09-23 수정). 처음엔
  상대경로였고 Next가 `metadataBase`(= `SITE_URL` = 프로덕션)로 채웠다 — dev에 배포해 카톡에 붙였더니
  `og:image`가 `https://gigang.team/api/og/...`를 가리켰고 거긴 라우트도 모임도 없어 404, **카톡은
  빈 흰 칸**을 띄웠다. 지면(`og:url`·canonical)은 프로덕션을 가리켜도 되지만 이미지는 반드시 그 지면을
  내준 호스트가 내줘야 한다. 카톡이 한 번 긁은 링크는 캐시가 남으므로 고친 뒤엔
  [카카오 OG 캐시 초기화](https://developers.kakao.com/tool/clear/og)에 URL을 넣어 비운다.
- **`openGraph`는 루트와 깊은 병합이 안 된다** — siteName·locale·type을 페이지에서 다시 적는다.
  `canonical`은 `/schedule` 고정.
- **KS X 1001 밖 한글·한자는 빈 네모.** 모임 제목에 실제로 쓰이면 `app/fonts/og/README.md`대로 범위를 넓혀
  다시 생성한다.

### dev 서버에서만 보이는 로그 — 고장 아님

봇 UA(`facebookexternalhit` 등)로 `/schedule`을 열면 dev 로그에
`Invariant: Route "/schedule" did not produce a static shell and Next.js was unable to determine a reason`
가 찍힌다(응답은 200). `cacheComponents` + **블로킹 메타데이터(html-limited bot)** + `searchParams`를 읽는
`generateMetadata` 조합에서 dev의 검증 렌더가 이유를 못 잡는 Next 16.1 쪽 문제다 — `?gthr=` 유무와 무관하게
`searchParams`를 읽는 순간 메타데이터가 동적이 되어 생긴다. 일반 UA·`pnpm build`·프로덕션에서는 안 난다.

---

## 결론: 된다. 막는 것 없음

`app/(main)/schedule/page.tsx`의 고정 `export const metadata`를 `generateMetadata({ searchParams })`로
바꾸면 된다. `searchParams`는 **`page.js`에서만** 받을 수 있는데(`layout`은 불가) 여기가 page라 조건이 맞는다.

선례가 이미 있다 — `lib/queries/board.ts`의 `getCachedBoardPost` + `app/(board)/board/[id]/page.tsx:14`의
`generateMetadata`. 그 모양을 그대로 가져오면 된다.

## 함정 두 개

**1. `cacheComponents: true`.** Next 16 문서상 `generateMetadata`가 `searchParams`를 읽는데 페이지의
나머지가 전부 prerender 가능하면 **빌드가 에러를 낸다**(`blocking-prerender-metadata-runtime`).
이 페이지는 `getCurrentMember()`가 쿠키를 읽는 동적 부분이 Suspense 안에 이미 있어서 "다른 부분도
request time으로 미뤄지는" 쪽에 해당할 것으로 보이지만 — **`pnpm build`를 돌려봐야 확정이다.**
걸리면 문서 처방은 `connection()`을 쓰는 `DynamicMarker` 한 줄 추가.

**2. 카카오 캐시.** 카톡 스크래퍼 UA가 `facebookexternalhit/1.1; kakaotalk-scrap/1.0` 형태라
Next 기본 `htmlLimitedBots` 정규식에 **이미 걸린다**(`node_modules/next/dist/shared/lib/router/utils/html-bots.js:15`).
즉 메타데이터가 스트리밍되지 않고 `<head>`에 블로킹으로 박혀 나간다 — 추가 설정 불필요.
다만 카카오가 URL별로 스크랩 결과를 캐시하므로 **이미 뿌려진 링크는 바로 안 바뀐다.**

**canonical은 `/schedule` 고정 유지.** 안 그러면 `?gthr=` 변형마다 별개 문서가 되어
「동일 제목 다수」가 재발한다. OG는 canonical과 무관하게 읽힌다.

## 시안 4안과 결론

| | 안 | 성격 |
|---|---|---|
| A | 전광판 | board 존 그대로. 카톡 배경에서 제일 튐 |
| B | 편집면 | 일정 탭 editorial 양식. 흰 지면에 붙여도 이물감 없음 |
| C | 달력 | 왼쪽 날짜 블록이 **종목색**(`sprt_cd` → `--sport-*`) |
| D | 미니멀 | 제목 하나. 작아져도 버티지만 밑 텍스트와 중복 |

**시안을 뽑고 나서 바뀐 판단**: 카톡 썸네일 실제 폭이 **246px**이라 카드 안 장소·시간 글씨는
사실상 안 읽힌다. 정보를 실어 나르는 건 그 밑 `og:title` / `og:description` 텍스트다.
그래서 이미지 역할은 "무슨 벙인지 0.2초에 감 잡게 하기"까지고, 그 기준이면 **C**가 제일 낫다
(246px에서도 종목색과 큰 날짜 숫자는 남는다). D는 제목만 남는데 그건 어차피 밑에 또 나온다.

**권장 조합**: 이미지 C안 / 텍스트는 제목 + `9월 24일 (수) 저녁 8:00 · 뚝섬유원지역 3번 출구`.

## 두 단계로 나눌 수 있다

1. **텍스트만** — `generateMetadata`로 `og:title`·`og:description`만 모임별로. 이미지는 기존
   `app/opengraph-image.png` 그대로. 체감 정보량의 대부분이 여기서 나온다. 반나절.
2. **이미지까지** — `next/og` `ImageResponse` 라우트 핸들러(`/api/og/gathering?...`)를 만들고
   `openGraph.images`에 URL로 물린다. `opengraph-image.tsx` 파일 컨벤션은 `searchParams`를
   못 받으므로 **반드시 라우트 핸들러 쪽.** Satori는 시스템 폰트를 못 써서 Pretendard·Oswald를
   실어야 하고, 한글 글리프를 통째로 올리면 함수가 무거워진다(제목 글자만 동적 서브셋하는 처리 필요).

1을 먼저 해도 2가 기존 코드를 건드리지 않는다.

시안 A·B·C는 Satori 지원 CSS만으로 그렸고, D의 `radial-gradient` 번짐만 `backgroundImage`로 고쳐야 한다.

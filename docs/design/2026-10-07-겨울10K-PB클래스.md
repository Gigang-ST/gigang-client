# 겨울 10K PB 클래스 — 설계 (1단계 모집·출석·환급 · 2단계 팀·목표·기록 · 3단계 점수판·정산)

> 이슈: GitHub #577 (본문 + 보강 댓글 2026-10-07 오너 확정). 규칙의 정본은 이슈이고,
> 이 문서는 **앱이 그 규칙을 어떻게 담는가**의 정본이다.
> 범위: 1~3단계 전부(2026-10-07 하루에 구현). 2·3단계는 문서 끝 §2·3단계.

## 한 줄 요약

마일리지런이 「각자 뛴 거리」로 환급했다면 PB 클래스는 **「공식훈련 벙에 나온 횟수」**로 환급한다.
관리자가 어떤 벙이 공식훈련(또는 10K 측정)인지 프로젝트에 **연결**하고, 출석은 그 벙의
`gthr_attd_rel`을 세서 낸다. 앱에 출석부를 새로 만들지 않는다 — **앱 참석 기록이 곧 출석부다.**

## 확정 규칙 (이슈 요약 — 숫자는 전부 관리자 설정값)

| 항목 | 값 |
|---|---|
| 회차 | 공식훈련 W1~W12(매주 수 19:30) + 10K TT 측정 1회 = **13회** |
| 주 경계 | **수요일 00:00 ~ 화요일 23:59 KST**, 벙 `stt_at` 기준. W1 = 프로젝트 `stt_dt`(2026-11-04 수) |
| 납부 | 정식·W2~W5 합류: 4만 원(보증금 3만 + 참가비 1만) / W6 이후 합류: 1만 원(보증금 없음) |
| 전액 기준 | `floor(남은 회차 × 9 ÷ 13)` — W1 9 · W2 8 · W3 7 · W4 6 · W5 6. W6+ 환급 없음 |
| 남은 회차 | `13 − (합류주차 − 1)` — **연결된 벙 수를 세지 않는다**(한파 취소로 연결이 빠져도 분모 고정) |
| 환급 | `floor(보증금 × min(출석, 기준) ÷ 기준)` 원 단위 내림 |
| 출석 | 연결된 벙 중 **합류 주차 이후**·**이미 열린(시작 시각 지남)**·**삭제 안 된** 벙의 참석만 |
| 한파 취소 | 그 회차는 전원 불참. 분모 안 바꿈 |

## 데이터 모델

### 왜 참가자 테이블을 마일리지(`evt_team_prt_rel`)와 공유하지 않나

이슈는 `evt_team_prt_rel` 재사용(+ `init_goal`·`stt_mth` NOT NULL 해제)을 제안했지만, 그 테이블을
**타입 구분 없이** 읽는 곳이 이미 여럿이다(2026-10-07 전수 확인):

- 칭호 `mileage_joined`(시작이반) 평가가 그 테이블에 행이 **하나라도** 있으면 준다 → PB 신청만으로 마일리지 칭호가 붙는다.
- 칭호 스냅샷(`lib/titles/snapshot.ts`)이 참가 행을 `mem_id` 하나로 키잉한다 → 두 프로젝트에 참가한 사람의 행이 서로 덮인다.
- MCP 마일리지 도구의 참가 해석(`lib/mcp/mileage.ts` `resolveMyParticipation`)이 "기간 중인 이벤트"를 우선 고른다 →
  11월엔 PB 참가를 마일리지 참가로 집어 기록을 엉뚱한 곳에 쓴다.

전부 막을 수는 있지만 **앞으로 그 테이블을 읽는 모든 새 코드가 타입 필터를 기억해야 한다.**
PB 전용 컬럼(합류 주차, 2단계의 훈련팀·게임팀·목표 기록)도 마일리지 행에 null로 붙게 된다.
그래서 **참가자는 `evt_pb_prt_rel`로 가르고, 프로젝트 자체(`evt_team_mst`)만 공유한다.**
→ 마일리지 코드는 PB 행을 볼 수 없어 구조적으로 안전하다.

`evt_team_mst`는 공유하므로 **"ACTIVE 이벤트 하나"를 집던 곳**만 타입 필터를 단다(§교차 영향).

### 테이블 (마이그레이션 `20261007120000_evt_pb_class.sql` + 인덱스 `20261007120100_evt_pb_class_idx.sql`)

```text
evt_pb_cfg          프로젝트별 설정 (evt_id PK → evt_team_mst, ON DELETE CASCADE)
  tot_sess_cnt        smallint  13   보증금 출석 총 회차
  full_rfnd_attd_cnt  smallint   9   정식 참가자 전액 환급 기준 (≤ tot_sess_cnt)
  late_join_wk_no     smallint   6   이 주차부터 합류하면 보증금 없음
  deposit_amt         integer 30000  보증금
  entry_fee_amt       integer 10000  참가비

evt_pb_prt_rel      참가자 (prt_id PK, UNIQUE(evt_id, mem_id))
  evt_id → evt_team_mst (CASCADE), mem_id → mem_mst
  join_wk_no          smallint  합류 주차 (1 = 정식)
  deposit_amt / entry_fee_amt   실제 낸 금액 — 환급 계산은 **이 행의 deposit_amt** 로 한다
  aprv_yn / aprv_at   입금 확인 (마일리지와 같은 의미)

evt_gthr_rel        공식훈련·측정 벙 연결 (gthr_id PK — 벙 하나는 프로젝트 하나에만)
  evt_id → evt_team_mst (CASCADE)
  wk_no               smallint  주차. **회차가 아니다** — 측정을 W14에 하면 13번째 회차가 wk_no=14
  sess_type_cd        'TRAINING' | 'MEASURE'
  UNIQUE(evt_id, wk_no), 측정은 프로젝트당 하나(부분 유니크 인덱스)
```

- `wk_no`는 **서버가 벙 `stt_at`에서 계산해 저장**한다(클라이언트가 보내지 않는다). 벙 날짜가 나중에 바뀌면
  저장값과 계산값이 어긋날 수 있어 관리자 회차 탭이 불일치를 경고로 띄운다(연결을 풀고 다시 걸면 고쳐진다).
- RLS: 세 테이블 모두 **SELECT = 같은 팀 멤버**(`v2_rls_auth_in_team(evt_team_mst.team_id)`), 쓰기 정책 없음
  → 모든 쓰기는 서버 액션의 service role(`createAdminClient`). 마일리지 테이블과 같은 방식이되,
  마일리지의 `USING (true)`(전 팀 공개)는 따르지 않는다.
- `database.types.ts`는 **재생성하지 않고 세 테이블 블록을 손으로 추가**한다(KNOWLEDGE §dev/prd drift).

### 출석 판정 (`summarizeRefund`)

연결 행마다 `held = !gthr.del_yn && gthr.stt_at <= now`를 붙여 넘긴다. `gthr_attd_rel`은 **미래 벙의 참석
예약까지 담는 테이블**이라(행 = 참석 확정, 노쇼는 운영진이 지운다), 시작 전 벙을 세면 아직 안 간 회차가
출석으로 잡힌다. 삭제된 벙(한파 취소)도 세지 않는다 — 전원 불참.

## 화면

### 프로젝트 탭 (`/projects`)

- 팀의 ACTIVE 프로젝트를 **전부** 읽는다(`stt_dt` 최신순). 둘 이상이면 상단 세그먼트로 고르고 `?evt=<evt_id>`로
  유지한다. 기본은 최신 시작. 예전엔 `.maybeSingle()`이라 ACTIVE가 둘이면 에러 → 소개 화면으로 떨어졌다.
- 마일리지 뷰는 기존 그대로(별도 컴포넌트로 옮김). 월 이동 링크가 `?evt`를 잃지 않게 한다.
- PB 뷰:
  - 미신청: 규칙 요약 + 「참가 신청」(지금 주차 기준 금액 — 4만 원 / 1만 원) → 신청 후 입금 대기 카드(계좌 복사).
  - 참가 중: **내 출석 `n / 남은 회차`**(정식은 `n / 13`) · **환급 예상액** · **전액까지 N회** + 13칸 회차 띠
    (출석/결석/예정/미지정/합류 전). 늦은 합류자는 환급 줄 대신 "보증금 없이 참가 중" 안내.

### 관리자 (`/admin/mileage` — 화면 이름은 「프로젝트 관리」)

- 정보 탭: 타입에 `PB_CLASS`(겨울 PB 클래스) 추가. PB면 설정 5칸이 같은 폼에 붙는다.
- 탭은 타입별: 마일리지 = 정보·배율·목표·참여자 / PB = 정보·회차·참여자.
- 회차 탭: 연결된 벙(주차·종류·날짜·참석 인원·주차 불일치 경고) + 「벙 연결」(프로젝트 기간 안의 미연결 벙 목록에서 고르고 종류 선택) + 연결 해제.
- 참여자 탭: 합계(참가 인원·보증금·환급 예정·미환급 풀·참가비) + 참가자별 합류 주차·출석/기준·환급·미환급 + 승인/승인취소/삭제/수정(합류 주차·금액) + **관리자 직접 추가**(카톡·계좌로 먼저 받은 사람 — 이슈의 1단계 지연 대비책).

## 2·3단계 — 팀·목표·기록 / 점수판·정산

### 점수는 저장하지 않고 매번 계산한다

이슈는 장부형(`evt_pt_hist`)을 제안했지만 **개인 점수는 전부 벙·참석·기록에서 자동으로 나온다**(#577 보강 3번).
장부를 따로 쌓으면 원천과 장부가 갈라질 자리만 생기고, "배점이 바뀌면 다시 계산"은 매번 계산하면 공짜로 된다.
그래서 `lib/pb-class-score.ts`의 `computeScoreboard`가 원천에서 바로 점수판을 낸다. 팀 미션은 오너 지시로 없앴다(아래 §피드백 2) —
관리자가 손으로 넣는 점수는 하나도 없다.

### 테이블 (`20261007130000_evt_pb_class_game.sql`)

| 테이블/컬럼 | 내용 |
|---|---|
| `evt_pb_cfg.rule_json` | 배점·목표 규칙(jsonb). 빠진 값은 `PB_DEFAULT_RULE`로 채운다(`ruleFromJson`) |
| `evt_pb_grp_mst` | 게임팀(이름·색 `color_no` 1~5 → `bg-chart-N`·순서) |
| `evt_pb_prt_rel.trn_grp_cd / grp_id / goal_sec` | 훈련팀(A~E) · 게임팀 · 10K 목표(초) |
| `evt_pb_rec_hist` | 측정 기록 `BASE_5K`·`MID_5K`·`FINAL_10K`·`DAEGU_10K` — **회원이 직접 올리고 바로 반영**(`cnfm_yn`은 늘 true) |

### 점수 규칙 (기본값 — 전부 `rule_json`으로 바꿀 수 있다)

| 코드 | 점수 | 조건 |
|---|---|---|
| `ATTEND` | 10 | 공식훈련·측정 벙 참석(합류 주차 이후) |
| `JOIN` | 3 | 공식훈련 **외** 팀 벙 참석(종류 무관, 프로젝트 기간 안) — **본인 포함 2명 이상 모인 벙만**(`joinMinAttd`, 혼자 연 벙으로 점수를 쌓지 못하게) |
| `HOST` | 5 | 본인이 연 공식훈련 외 벙에 **본인이 참석하고** 본인 포함 3명 이상 |
| `IMPROVE_MID` | 1%마다 3, 최대 15 | W1 기준기록 → W6 5K (정식 참가자만) |
| `IMPROVE_FINAL` | 1%마다 3, 최대 30 | 기준 5K × 2.085 → 측정 10K (W2~W5 합류자는 W6 5K가 기준) |
| `GOAL` | 20 | 측정 10K ≤ 개인 목표 |
| 팀 `ALL_ATTEND` | 주당 20 | 그 주 등록 팀원 전원이 공식훈련·측정 참석 |

- **팀 점수 = Σ주차(그 주 등록 팀원 1인당 평균) + 전원 출석.** 합류 전 주차엔 분모에도 없다.
- **늦은 합류(W6+)는 팀전 밖** — 점수 0, 목표 달성 배지만(`goalAchieved`).
- 기록은 회원이 직접 올린다(운영진은 잘못 들어간 값만 고친다). 최종 기록 점수는 **측정 벙이 연결돼야** 붙는다(그 주차에 들어간다).
- 대구마라톤 기록은 팀 점수에 넣지 않는다(신청이 자유라 신청자 많은 팀이 유리해진다).
- 목표는 회원이 W2(`goalEditUntilWk`)까지 고치고, 이후엔 관리자만. 상한 60분(`goalMaxSec`).

### 화면
- 회원(승인): 내 팀 · 목표 · 내 기록(대구 본인 입력) · 점수판(팀 순위 + 내 점수 내역) · 정산(합계 + 참가자별 환급액).
  점수판은 미참가자·입금 대기자에게도 보인다(구경거리). 정산은 승인된 참가자에게만.
- 관리자 PB 탭: 정보 · 회차 · 참여자 · **팀**(게임팀 CRUD·배정·뱀 드래프트) · **기록**(회원 입력값 고치기) · **점수**(점수판·배점).

## 남긴 것

- MCP(`gigang-ops`) 도구 — 점수판·환급 조회를 붙이려면 `lib/queries/pb-class*.ts`가 이미 클라이언트 주입식이라 그대로 쓴다.
- 시상(개인 기록상 등)·정산 확정(환급 지급 완료 표시)은 운영이 정할 때 붙인다. 지금 정산은 「현재 기준 예상」이다.

### 기록 입력
- 시각 칸은 `mm:ss`·`h:mm:ss`와 **숫자만**(`2530` = 25:30, `10203` = 1:02:03)을 받는다. 폰 숫자 키패드엔 `:`가 없어서,
  숫자만을 초로 읽으면 25:30이 42:10으로 저장돼 기록 점수가 통째로 틀어졌다(리뷰 P1). 기록 하한은 서버도 10분.

| 시작일 정하면 종료일 자동 | PB는 **서버가** `pbEndDtFor(시작일, 설정)` = 시작 + (총회차+1)주 − 1일로 저장(11/4 → 2/9). W12 날짜로 끊어 측정 벙 연결이 막히던 일이 실제로 있었다 |
| 마일리지런 참가자 보증금 5천 원 할인 | `evt_pb_cfg.mlg_dc_amt`(기본 5,000). 같은 팀 `MILEAGE_RUN`에 **승인된** 참가 이력이 있으면 신청 때 깎고 `evt_pb_prt_rel.deposit_dc_amt`에 남긴다. 환급은 **실제로 낸 보증금** 기준 — 9회면 25,000원 전액 |
| 종료하면 삭제 말고 보관 | 「프로젝트 종료」 = `CLOSED`. 회원 탭에선 내려가고 맨 아래 「지난 프로젝트」에서 읽기 전용으로 연다. **참가자가 있으면 삭제 불가**(마일리지 삭제가 참가자·기록을 통째로 지우던 것) |
| 규칙이 곧 안내사항 | 규칙 카드·규칙 시트를 걷고 PB 뷰의 **안내** 탭 하나로 — 숫자는 전부 설정·배점·데이터에서 |
| 주차별 훈련 내용과 목적 | `evt_pb_sess_plan`(회차별 제목·세션·비고 — 2026-10-08부터 단계·목적 대신 훈련 종류·개인 훈련, §훈련표 확정) + 회원 **훈련** 탭. 기본값은 `lib/pb-class-plan.ts`(운영 레포 상세계획 §5, 「목적」은 새로 씀) |

- PB 뷰는 히어로(기간·지금 n주차·다음 공식훈련·내 출석) + 탭 「내 현황 · 훈련 · 점수판 · 안내」(`?view=`).

# 칭호획득 리드 슬롯 v2 — 사람 대표 + 하단 명단

> 2026-08-12 · v1(칭호별 묶음 나열)을 dev 실데이터 화면으로 본 뒤 갈아탄 개정판.
> **v1 스펙**(2026-08-07-칭호획득-리드슬롯-design.md)의 지면 설계·응원 결정을 이 문서가
> 대체한다. **데이터 설계(RPC·쿼리·캐시)는 v1 그대로다 — 마이그레이션 없음.**

## 배경 — v1이 지면에서 실패한 이유

v1은 "수십 명이 한꺼번에 따는 sweep이 이 슬롯의 존재 이유"라 보고 칭호별 묶음 나열을
골랐다. dev 실데이터로 화면을 세워 보니 세 문제가 겹쳤다(사용자 피드백: "휑하고,
아바타만 있어서 누군지도 모르겠다"):

1. **이름이 지면에 하나도 없다.** 24px 아바타만 나열되는데 프사 미설정 멤버는 DiceBear
   랜덤 얼굴이라 사실상 익명이다. 다른 슬롯은 전부 이름이 주연이다.
2. **평상시 데이터가 sweep 가정과 다르다.** 칭호당 1~2명짜리 줄이 대부분이라 얇은 줄
   3개의 오른쪽이 텅 빈다. sweep은 이벤트고, 지면은 평상시에 서 있어야 한다.
3. **응원이 없다.** "여러 칭호 × 여러 사람이라 대상 불성립"으로 뺐는데, 그 결과 footer
   오른쪽까지 비어 휑함을 더한다. 나머지 여섯 슬롯은 모두 응원이 있다.

## 결정 요약

| 쟁점 | 결정 | 근거 |
|------|------|------|
| 슬롯 주인공 | **사람 대표 1명(회전) + 하단 얼굴+이름 칩 명단** | 다른 사람 슬롯(활동지수·목표)과 같은 문법으로 회귀. sweep 가시성은 하단 명단이 잇는다 |
| 우측 레일 | **기각** | 은퇴한 문법(story-lede.tsx buildLedes 주석 — "우측 레일 대신 시간으로 모두에게 자리를 준다"). 이 슬롯만 레일이면 새 어법 발명 |
| 회전·명단 단위 | **사람** — 사람별 최신 수여 1건으로 dedupe | 한 사람이 칭호 셋을 동시에 따도 대표 3연속·명단 3중복이 안 되게. 목표 팻말 `dedupePledgesByMember`와 같은 원칙 |
| 헤드라인 | `{이름}, 새 칭호를 획득하다` | 칭호명을 넣으면 을/를 조사가 칭호마다 갈린다(山神을/HALF를). 칭호명은 배지가 실물로 말한다. "달다"는 화면에서 보고 "획득하다"로 굳혔다 |
| 칭호 설명(`ttl_desc`) | **대표 오른쪽 글상자**(화면 검토 2회 거쳐 정착) | 처음엔 대표 *아래* 한 줄이었는데 명단을 밀어내 걷어냈고, 걷어내고 보니 대표 블록 오른쪽이 통째로 비었다. 그 자리에 상자로 넣으면 명단은 그대로 올라오고 설명도 산다. 배지 툴팁은 유지(좁은 화면에서 잘린 뒷말) — **게이트는 `resolveDescVisible` 하나를 공유**한다 |
| 명단 스크롤 | **없앤다** — `TITLE_OTHERS_MAX`(8)에서 자르고 `외 N명` | 4초마다 넘어가는 지면에서 스크롤은 손이 닿기 전에 사라지는 조작이다. 두 줄로 상한을 두면 높이도 상한이 생겨 264px 예산이 구조적으로 지켜진다 |
| 명단 칩 | **얼굴 위 · 이름 아래** 세로 스택 | 이름을 옆에 두면 칩 폭이 `아바타+이름`이라 한 줄에 서너 명뿐인데, 아래로 내리면 폭을 이름이 정해 같은 두 줄에 두 배가 선다 |
| 응원 | **부활** — `actv` + 대표 mem_id | 대표가 한 명이라 대상이 성립한다. 활동지수·목표·깅스타그램과 같은 멤버 기준 카운터(같은 사람이 여러 슬롯 대표면 🔥 합산 — 기존 의도) |
| RPC | **`total_mem_cnt` 한 필드 추가**(20260812100000) | `외 N명`은 사람을 세는데, `grants`가 칭호당 10건에서 잘려 클라이언트가 세면 **적게 나온다**(prd 실측 75명 → 41명). 하필 그 오차가 벌어지는 때가 sweep이라 계기가 거짓말을 한다 |

## 지면 설계

```
┌──────────────────────────────┐
│ 기강에 새 역사를 쓰다         │ ← kicker (유지)
│                              │
│ 홍기강, 새 칭호를 달다        │ ← 헤드라인 (hero: "headline")
│                              │
│  ◉ 홍기강    ┌─────────────┐│ ← 대표: Avatar(md) + [이름/배지] 세로 단,
│    [山神✨]  │트레일런 PB  ││    오른쪽 남는 폭에 칭호 설명 글상자
│              │남녀 각각 1위││    (높이 h-12 고정 · 2줄에서 …)
│  ────────────────────────── │ ← 괘선
│  ◯   ◯   ◯   ◯   ◯   ◯    │ ← 나머지 획득자: 얼굴 위·이름 아래 칩,
│ 한세희 함용석 기지현 …        │    **한 줄** 고정(최대 6명)
│  외 66명                     │ ← 남은 인원은 그 아래 제 줄
│ 최근 획득 143건       🔥 12  │ ← footer: 30일 창 수여 건수 + 응원(부활)
└──────────────────────────────┘
```

- **대표 블록**: `Avatar`(md) + **[이름 / 칭호 배지] 세로 단** + 오른쪽 남는 폭에
  칭호 설명 글상자. 얼굴·이름 탭 → 프로필 카드, 배지 탭 → 같은 설명 툴팁.
  - **칭호는 이름 밑이다**(가로 나열 아님) — 이름 옆에 두면 배지가 설명 글상자와 가로로
    경쟁해 셋 다 좁아진다. 세로 단으로 묶으면 이름·배지가 한 덩어리로 읽히고 상자가
    남는 폭을 온전히 쓴다.
  - **아바타가 lg가 아니라 md인 건 높이 때문이다**: 이름(17) + 간격(4) + 배지(19)가
    정확히 40px이라 두 덩어리 높이가 맞고, lg(56) 대비 **16px을 슬롯에 돌려준다**.
  - **얼굴과 이름이 버튼 둘로 갈린다** — 배지가 버튼 밖에 있어야 하는데(배지 탭은 툴팁,
    얼굴·이름 탭은 카드) 배지가 이름 밑으로 내려오면서 한 버튼으로 묶을 수 없어졌다.
  - 글상자에 **인용부호를 쓰지 않는다** — 여기 있는 건 사람의 말이 아니라 칭호에 붙은
    설명이라, `IntroQuote`의 어법을 빌리면 본인이 한 말처럼 읽힌다.
  - **높이 `h-12` 고정 · 2줄에서 `…`** — 설명 길이가 칭호마다 제각각이라 열어 두면
    대표 블록이 한 줄짜리·두 줄짜리를 오가고, 4초마다 넘어가는 지면에서 아래 명단이
    위아래로 뛴다. 잘린 뒷말은 배지 툴팁에서 읽는다.
  - 노출 게이트(`desc_visibility`)는 툴팁과 **같은 `resolveDescVisible`**을 탄다.
    지면과 툴팁이 각자 판정하면 `held`·`never` 설명이 한쪽에만 새어 나간다.
- **하단 명단**: 대표를 뺀 나머지 획득자(사람 dedupe 후)를 **얼굴 위·이름 아래** 세로
  스택 칩으로(xs 아바타 + 12px 이름, 탭 → 프로필 카드). 순서는 **최신 수여일 순 고정**.
  `TITLE_OTHERS_MAX`(6)에서 자르고 남은 인원은 **`외 N명`** — 얼굴 줄 **아래 제 줄**에.
  - **한 줄이다.** 두 줄로 늘렸다가 되돌렸다 — 두 줄(+46px)은 헤드라인이 2줄이 되는
    순간 바닥이 잘린다(실제로 잘린 화면을 봤다). 264px은 전 슬롯 공통 예산이라 이 존
    하나 때문에 못 늘린다.
  - `flex-nowrap` + 칩마다 `min-w-0 flex-1` — 이름 길이가 사람마다 달라 고정 폭이면
    긴 이름이 들어온 날만 줄이 넘어간다. 남는 폭을 나눠 가지면 **한 줄이 무조건
    지켜진다.**
  - **이름은 자르지 않는다**(`whitespace-nowrap`만, `truncate` 아님). 칸이 좁으면 옆
    이름과 겹치게 둔다 — 이 줄에서 알아야 할 건 "누가 받았나"인데 `…`로 잘리면 그걸
    못 읽는다. 겹쳐도 읽히지만 잘리면 안 읽힌다. 줄바꿈만 막으면(두 줄로 접히면 칩
    높이가 달라져 한 줄 배치가 무너진다) 넘친 글자는 폭을 늘리지 않고 시각적으로만 흐른다.
  - `외 N명`을 칩 옆에 끼우지 않는 이유: 그 자리 하나가 얼굴 몫에서 빠지는데 여섯이
    꽉 차는 줄이라 한 자리가 아깝다.
  - **`외 N명`은 반드시 `total_mem_cnt`로 센다**(`countTitleMoreMembers`). pool 길이로
    세면 grants 10건 상한 탓에 적게 나온다 — 회귀 테스트가 prd 실측 형태(75 vs 41)로
    이 규칙을 못박는다.
- **footer**: 왼쪽 `최근 획득 {G}건`(`grant_cnt` 합산). **"최근"을 붙인다** — 맨숫자만
  두면 크루가 여태 딴 칭호를 다 합친 값으로 읽히는데 실제로는 30일 창의 집계다. 일수는
  적지 않는다(창 길이는 RPC 기본값이고 지면이 이미 "요즘 소식"으로 읽힌다).
  오른쪽 응원 버튼 — `buildEntity("actv", 대표.mem_id, "fire")`.
- **스와이프 순서**: `… → record → title → race`(v1의 맨 뒤에서 한 칸 앞으로).
  해낸 일(완주기록) 옆에 그 결과로 받은 것(칭호)을 붙이고, 앞으로의 일(대회)을 맨 끝에
  둬 지면이 "지나온 것 → 다가올 것"으로 닫힌다.
- **빈 상태**: v1 유지 — pool이 0이면 슬롯을 아예 만들지 않는다.

### 회전 규칙 (v1의 "3개 페이지 전진" 폐기)

- pool = grants 평탄화 → **사람별 최신 수여 1건 dedupe** → `grnt_at` 내림차순. 길이 P.
- 대표 = `rotate(pool, titlePick)[0]`. 명단 = pool − 대표, **최신순 고정**(회전과 무관 —
  매 바퀴 명단까지 뒤섞이면 어지럽다).
- `initialTitlePick`은 서버가 뽑는다(v1 유지, 이제 P 기준). 한 바퀴 완주마다
  `titlePick += 1`(v1의 `+= 3` 대체) — 모든 획득자가 돌아가며 대표가 된다.
- sweep 칭호는 RPC 상한 때문에 최신 10명까지만 pool에 든다 — 대표 회전도 그 안에서
  돈다. 허용: 지면에 세울 사람은 대표 1 + 명단 8이면 충분하고, **인원 총량은
  `total_mem_cnt`가 따로 지킨다**(`외 N명`이 정확한 이유).

### 264px 예산

kicker + 헤드라인(1~2줄) + 대표 블록 + 괘선 + 명단(가변·스크롤) + footer. 명단이
`flex-1 + overflow-y-auto`라 세로 예산 초과가 구조적으로 없다(대회 슬롯과 동일).
**실측은 375px 기기 에뮬레이션**(DESIGN.md 경고 — 창 줄이기 방식 금지), 화면 확인은
사용자 몫(관례).

## 응원 검증 확장 (구현 필수)

`bump-reaction`의 `actv` 검증 출처가 현재 3개(활동지수 랭킹 · 목표 팻말 · 깅스타그램
작성자)다. **네 번째 출처로 칭호획득 pool(`story-titles` 캐시)을 추가**한다 — 검증은
"이 mem_id가 지면에 서 있는가"이므로 대표만이 아니라 **pool 전체**(회전으로 누구든
대표가 된다)를 본다. 빼먹으면 대표에게 응원을 누를 때 서버가 거부한다.
DESIGN.md의 "세 출처" 서술도 함께 갱신한다.
